# Dashboard and dynamic-route migration map

**Status:** Source route inventory is complete. Staging covers the mapped public routes and dashboard families, but route/feature presence is not full visual or behavioral parity. Local D1 backs synthetic admin sessions/Profile, source-shaped Property/File, taxonomy/Maps, Landing Page, Query admin, and all eight Calculator tables. Calculator public config and protected admin CRUD now use D1; Rates/Transfer Fees CSV preview and transactional import use current D1 state. Fee Rule `is_active` and per-domain active filtering/order match the checked-in SQL/PHP contract. The formula module remains unchanged; current golden cases are representative, not exhaustive PHP execution. Property/File/Map and dashboard forms still need visual/behavior comparison. Media uploads remain disabled, users are read-only, and production records/APIs remain out of scope. The legacy Calculator Fee Rules PDF action is toast-only and has no CSV import UI.

## Staging implementation boundary

- The staging frontend remains `apps/staging-web/`; the isolated JavaScript API remains separate from the legacy PHP API and `workers/ai-worker`.
- Use versioned API contracts and repository interfaces. Local D1 adapters back synthetic auth/Profile, source-schema-aligned Property/File/taxonomy/Maps/Landing Page/Query/Calculator data. Property/File API projections are allowlisted; media remains unlinked. Migration 0007 bridges prior synthetic Property rows, while old transition tables are retained. Remote D1 remains a separate approval after schema/query/free-budget review. Media upload/storage remains excluded and needs a separate object-key design.
- The role is a single hardcoded `Admin` role shared by exactly two synthetic staging users. Do not build role management, invites, or user CRUD. Demo credentials are local-only and must not enter Git, plans, logs, or deployment configuration.
- Keep server-session and CSRF boundaries. Local sessions/Profile and Property records persist in the isolated Wrangler D1 simulator; this does not provision remote storage or authorize deployment. Any remote deployment requires separate approved storage, rotated/independent secrets, and explicit deployment authorization.
- Staging CRUD and fixtures must be synthetic only. Inquiry/contact/email sending, uploads, production MySQL/API access, domain/DNS changes, Cloudflare resource provisioning, and `workers/ai-worker` remain out of scope.
- Calculator public/admin adapters use local D1 and deterministic synthetic fixtures. Rates/Transfer Fee CSV preview reads D1 and apply uses a single transactional batch. The local database remains `remote: false`; any remote storage/deployment requires separate approval and cost-budget verification.

2. **Implemented locally:** Added loopback-only two-admin login/session/logout, a protected dashboard shell/home, a read-only two-admin account view, and versioned synthetic API auth/session gates. Direct API tests verify credential checks, seven-day cookies, concurrent independent sessions, CSRF, throttling, and local-host gating.

Landing Page content, visibility, selected numeric item IDs, popup delay, and embed text now persist in source-shaped local D1; its six synthetic sections keep fixed ID order/name/type, with no create/delete/reorder controls. 4. **Public frontend coverage:** `/`, `/about`, `/contact`, `/privacy-policy`, `/calculator`, `/properties`, `/properties/$slug`, `/maps`, and `/files` have staging routes. There is no current source Terms route. This measures route coverage, not exact design parity. Contact/newsletter actions remain disabled; media is placeholder-only; calculator uses synthetic D1 config and representative, non-exhaustive formula parity tests.
5. **Next:** Property and File APIs/admin operations now share source-shaped local D1 rows (`properties.is_file` distinguishes them) under ADR-028/029. Review remaining text domains and finish field-by-field form comparisons; Rates and Transfer Fees have bounded synthetic CSV import. Treat toast-only legacy PDF handlers as non-output stubs and do not invent a Fee Rules import workflow. Keep uploads and transactional messaging disabled and production data out of scope.

The Property/File APIs and protected admin paths share source-shaped local D1 rows, so synthetic publish/update/hide/delete changes affect subsequent public reads. Map, taxonomy, Landing Page, synthetic Query, and Calculator APIs also use local D1. Real Query policies, formula edge coverage, and visual parity remain open. The route labels and basic edit controls are intentionally generic rather than a visual/form parity claim for every legacy module.
