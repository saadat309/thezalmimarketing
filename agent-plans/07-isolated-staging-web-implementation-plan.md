# Isolated Staging Web Implementation Plan

**Status:** Approved for implementation by the user on 2026-10-17.
**Scope:** Local-only first public replacement slice in `apps/staging-web/`. No Cloudflare resource, deployment, production data, cPanel/PHP edit, DNS edit, email, admin auth, media upload, or AI work.

## Deliverable

An independent JavaScript/JSX Vite + React application that uses synthetic data and provides a coherent public staging experience:

1. Shared responsive navigation, footer, accessibility baseline, and visual design tokens.
2. Home, Properties, Property Detail, Maps, Files, and Calculator information pages.
3. Fixture repository modules for properties, maps, files, and taxonomies; no page reads a backend directly.
4. Browser-side canonical metadata updates, route-level titles/descriptions, filtered-listing canonicalization, plus static `robots.txt`, `sitemap.xml`, and `404.html` artifacts.
5. A rendered not-found view for unmatched browser paths.

## Implementation sequence

1. Create the isolated package manifest, Vite entry, application shell, global CSS, and local README. Reuse the repository-level installed development dependencies without changing the root app or lockfile.
2. Add synthetic fixture data and repository functions. Use generic placeholders and stable fabricated property/map/document records only.
3. Build the shared header/footer, home page, cards, filters, and content sections. Keep decorative imagery CSS-based so no production media is copied.
4. Implement client-side route resolution for the agreed public paths, including trailing-slash link generation and a not-found page.
5. Implement document metadata utilities. The staging base URL is an explicit local placeholder, never the production host. Filtered listing URLs canonicalize to `/properties/` and do not enter the sitemap.
6. Add static crawler artifacts. `404.html` supplies host-compatible not-found content; the later Worker/host runtime must set the actual HTTP 404 status.
7. Run build/lint-equivalent static checks and use a local browser session for responsive, metadata, route, accessibility, and console smoke checks.
8. Update project state/change log with checks actually run. Do not alter accepted decisions unless a new user choice is needed.

## Acceptance checks

- `npm run build` succeeds within `apps/staging-web/`.
- No `.ts` or `.tsx` file exists in `apps/staging-web/`.
- Synthetic fixture files contain neither production origin strings nor credentials.
- Known routes render useful content; a missing route renders the not-found view.
- `/properties/?category=...` filters the fixture list but uses the base listing canonical.
- Sitemap excludes query URLs and uses trailing-slash canonical entries.
- Root Vite/PHP files and `workers/ai-worker/` have no diff.

## Hosting limitation

The local Vite SPA can render not-found content but does not control the HTTP status generated by a future CDN/Worker fallback. A real HTTP `404` must be validated in the later approved Workers/hosting runtime spike; no runtime resource is created in this slice.
